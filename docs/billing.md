# 个人收款与人工核款

本版本支持个人支付宝 / 微信收款码、用户申报交易单号、管理员核实到账后发放次数。没有接入支付平台查询、异步支付回调或自动转账。

## 新用户免费体验

本功能上线后，新注册账号自动获得诊断 1 次、精修 1 轮、岗位适配 1 次、文字面试 1 场，无需创建订单或付款。每个账号仅赠送一次，不按天重置；登录、换设备、重设密码及服务重启不会再次发放。上线前已有账号不自动补发。

开启按次数使用时，系统优先预占该功能的赠送次数，用完后再使用已购次数。精修包含一轮追问与一次改写；面试支持 3 或 5 题，包含逐题反馈和复盘。生成最终失败会退回本轮次数，手动重试重新预占；重复点击、自动重试不会额外扣次。已交付结果的删除、提前结束面试或材料到期不会恢复已经使用的赠送次数。手动编辑、采纳和导出继续免费。

账号页显示免费体验与已购次数，并在次数记录中标明“新用户体验”来源。赠送次数不折现、不退款，也不会被购买订单的退款暂停或收回。关闭购买开关时仍沿用原有免费体验模式，不消耗尚未使用的赠送次数。

赠送与注册在同一个数据库事务内提交，`billing_welcome_grants` 以账号与功能作为唯一键。赠送使用同一份 `billing_usage` 账本，`order_id` 为空表示注册赠送，不生成零元或虚假支付订单。并发限制、失败返还、恢复码权限和原有注册 / AI 限流继续生效；赠送按账号识别，不代表已验证一个自然人只能注册一个账号。

## 首次启用

1. 为服务器单独生成 `BILLING_ADMIN_KEY`（`openssl rand -hex 32`），写入服务端 `.env` 后重启。它与 `DATA_ENCRYPTION_KEY` 不同，不能替换原数据加密密钥。管理密钥允许 32—128 个字符；不要提交到仓库或配置在前端。
2. 打开 `https://你的域名/#admin`，输入管理密钥；进入“收款与套餐”。
3. 上传真实 PNG / JPEG 收款码（1 MiB 以内，宽高 96—1,600 像素），填写可核对的收款名称、通常的核款时间和咨询 / 退款联系方式。自行扫码核对收款名称，保存配置。
4. 填写套餐价格及诊断 / 精修 / 岗位适配 / 面试次数。最多 5 个套餐；上架价格为 ¥1—¥1,000，每类次数为 0—100 的整数。至少包含一项服务。
5. 勾选“开放购买并按次数使用 AI 功能”并保存。未配置真实收款码、收款名称、说明、联系方式或有效上架套餐时，服务器拒绝开启。

新数据库默认关闭购买；默认套餐仅是未上架草稿，价格为 0。上传二维码或配置管理密钥不会自动开放购买。购买关闭时沿用原有免费体验与频率限制，已有订单仍可核款和处理售后；关闭开关也意味着新 AI 操作停止收费，请按实际运营安排使用。已经开启的付费轮次继续沿用原额度，失败返还和权限核对仍然有效。

新订单还要求模型服务已配置。`ready` 表示服务端配置可用，不是支付平台或模型供应商实时在线保证。

## 用户操作

用户先注册账号，查看次数规则并同意，再创建订单。网页展示该订单固定的金额、次数、收款名称、二维码及核款联系方式。付款后从支付宝 / 微信账单复制完整交易单号，点击“我已付款，提交核对”。这一步只进入待核款状态，余额仍为零。

管理员从 `/#admin` 打开待核款订单，在支付平台核对交易单号、金额、付款人和对应订单，然后手动输入实际金额及完整收款单号，勾选确认，发放次数。核对不成功时填写原因并退回补充。前台的申报单号和截图不能代替实际到账核对。

新订单保留收款机会 2 小时。过期、取消或退回补充后不再显示收款码；已经发生的付款仍可以提交交易单号核对，不会因为订单过期而无法售后。每账号最多 3 个未处理订单，下单和申报也有频率限制。

金额以整数分保存，从服务器已保存的套餐读取；客户端不能修改订单金额或发放次数。创建时接受 `manual-v1` 规则，套餐和收款资料形成加密快照，更改设置不会改变旧订单。请求标识确保下单重试返回同一订单；按支付渠道和规范化交易单号建立唯一约束，同一收款不能重复发放。

## 次数规则

| 功能 | 1 次 / 轮 / 场包含的内容 |
| --- | --- |
| 逐项诊断 | 一份完整的简历与 JD 对照报告 |
| 简历精修 | 一轮针对材料的追问，以及一次基于确认回答的改写；重新生成追问开启新一轮 |
| 岗位适配 | 一次针对选定版本和 JD 生成修改建议 |
| 文字面试 | 3 或 5 题的一场练习，包含逐题反馈与复盘；从薄弱点再练是新一场 |

生成任务与次数预占在同一 SQLite 事务内保存。首次结果成功后计次；精修的后续改写、面试的后续回答和复盘沿用本轮额度。自动重试不重复扣次。任务最终失败退回其关联额度，即使本轮此前已经成功交付过追问或面试题；之后手动重试重新预占。重复提交、队列满、授权或输入校验失败不会扣次。

精修完成一次改写后，本轮不能重复无限改写。付费面试最多 5 题；免费模式继续支持原来的 3 / 5 / 8 题。上线前已经开启的免费轮次可继续完成。恢复报告只授予材料访问权，不能花费另一个账号已经购买的轮次。

手动保存版本、采纳 / 拒绝建议、导出和查看固定示例不计费。取消或到期发生在首个结果成功前会释放预占；删除已交付内容、放弃追问、提前结束或删除已开始的面试不会退回已用次数。所有生成仍受原有队列与频率限制，限流不同于余额不足。

次数目前不设到期日。报告和全部准备材料最多保留 7 天，次数不会延长材料期限。当前前台展示最近 60 条次数记录；订单按每页 30 条查看，旧记录仍保存在数据库中。

## 退款与售后

1. 用户在已支付订单申请退款并联系运营者协商金额。该订单未用次数暂停使用；管理员开始处理前，用户可以撤回。
2. 管理员点击“开始退款处理”。此后用户不能自行撤回，后台显示剩余次数和正在生成的任务。等待关联任务结束后，再在支付宝 / 微信完成商定退款。
3. 输入本次实际退款金额、退款交易单号及说明，勾选“已实际退款”后登记。此操作仅记账，不会代替支付平台转账。后台拒绝正在预占或生成中的订单退款。
4. 每次登记退款都会收回该订单全部未用次数，并停止该订单已开启精修或面试的后续生成；已生成结果仍按材料期限保留。支持部分退款和多笔退款，累计金额不能超过原订单金额。退款单号去重，重复登记不会重复收回次数。
5. 不退款或协商变更时，管理员填写说明，选择结束退款处理；解除暂停。支付确认、退回补充、退款申请及处理均保留审计记录，交易及退款明细加密保存。

## 账号与运维

账号使用用户名（4—32 位字母、数字、下划线，不区分大小写）和密码（10—128 个字符），不依赖邮箱 / 短信。密码用随机 16 字节盐和 PBKDF2-SHA256 600,000 次迭代保存。注册和重设时显示一次 `JCA-` 账号恢复码，仅保存其摘要；账号名、密码和恢复码由本人保管。恢复码重设密码后会轮换，同时注销该账号全部旧会话。没有密码及有效账号恢复码时，系统不能仅凭报告恢复码找回购买权益。

注册 / 登录会更换会话令牌；勾选加入报告仅复制当前匿名会话的材料权限，不合并其他注册账号的报告或余额。普通会话为 HttpOnly、SameSite=Lax，生产使用 Secure。管理会话是独立的 HttpOnly、SameSite=Strict Cookie，仅作用于 `/api/admin`，8 小时过期，写操作有独立 CSRF。更换 `BILLING_ADMIN_KEY` 并重启会立即使旧管理会话失效。

当前 schema version 为 4。版本 3 新增账户、设置、收款码、订单、发放、使用、退款和审计表；版本 4 新增注册赠送表，将使用账本的订单引用改为可空，并在事务中保留全部历史使用记录、索引和结算触发器。升级前停止服务、备份受保护的数据与配置，沿用原 `DATA_ENCRYPTION_KEY`。旧报告、会话、恢复码、准备资料及购买余额保持有效。预占、成功扣次、失败退回及过期清理通过数据库事务与触发器共同保证，任务租约失效或进程重启后仍能结算。

账号、订单、交易与退款记录不随材料的 7 天保留期删除。用户名和账务索引用于查询，密码 / 恢复码仅保存派生值；收款图片、订单快照、申报 / 核对明细和退款说明使用原数据密钥加密。不要把数据库、环境文件、管理密钥或含材料的临时备份放进静态目录或源码仓库。备份仍需遵守材料到期策略，不能因保留账目而长期保留简历内容。
