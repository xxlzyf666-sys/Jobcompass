# 岗位罗盘视觉方案

面向后端开发求职者。页面的任务是让用户提交两份材料，并看懂每条岗位要求对应的经历依据。

色彩：纸白 #FFFFFF、冷白 #F4F7F5、墨绿 #183D36、玉绿 #24745E、浅绿 #E8F0EA、琥珀 #D99A34。正文弱化色和边线从墨绿通过透明度派生。

字体：标题使用本地 Noto Serif CJK SC / Songti SC；正文使用本地系统无衬线与 Noto Sans CJK SC；要求编号使用 ui-monospace。没有远程字体。

布局方案 A：长营销页后接上传区。缺点是用户需要先滚动才能开始。

布局方案 B（采用）：简短标题和一张真实结构的对照示例，下方直接并排输入；报告占据同一工作台，通过页内状态切换。

```text
品牌                    开始诊断 / 示例报告 / 我的报告
简短标题与说明           JD 片段 → 简历片段 → 补充问题
准备材料  ─────────  逐项对照  ─────────  整理修改
简历 / PDF 提取与检查       目标岗位 JD
数据说明与确认                         开始诊断
```

签名元素：两个真实引文之间的对齐线与琥珀标记。装饰服务于“依据来自哪里”，不增加抽象分数、虚构用户数量或无关插图。

二次检查：去掉泛化的增长数字和仪表盘；绿色只用于行动及有依据状态，琥珀色用于待确认。桌面双列在手机上改为连续步骤。报告导出采用清晰的黑白打印排版。

## 求职准备扩展（2026-09-13）

继续面向后端开发求职者，新增页面的任务是把报告变成能投递的简历与可继续的面试训练。沿用纸白 #FFFFFF、冷白 #F4F7F5、墨绿 #183D36、玉绿 #24745E、浅绿 #E8F0EA、琥珀 #D99A34；新增底色均由这些颜色派生。标题仍用本地 CJK 宋体，正文用现有无衬线，编号和状态用等宽字体。

比较了三张独立入口卡片和同一工作台的三个步骤：采用后者，避免重复上传及丢失资料上下文。当前版本选择器贯穿三个步骤，报告页提供直接入口。

```text
诊断报告 ←          求职准备          到期与恢复说明
简历精修            岗位版本          面试练习
当前版本 [选择简历]
已保存原文          追问 → 确认事实 → 原文 / 改写 → 逐条采纳
版本列表及新岗位 JD  正文编辑 → 保存 → 独立打印页
面试选择及设置      一题一答 → 对照回答复盘 → 再练薄弱点
```

签名元素从“JD 与经历对齐”延续到“原句与改写并排”。确认过的修改才能进入正文，视觉上的浅绿建议区对应待审核的新文本。面试采用有明确题号的连续记录，复盘贴近原回答。

检查后保留一个清晰的文字简历打印版，去掉装饰性分数、无关图表和额外模板。手机采用单列，操作按钮自动换行；截图检查了改写、版本和面试复盘。未保存的内容有提示，示例明确标注为固定虚构资料。
