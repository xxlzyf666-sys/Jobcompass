# 求职准备：简历精修、岗位版本与模拟面试

2026-09-13。由已完成诊断进入工作台，继续使用原报告的简历、岗位、访问权限及恢复码。界面保留三个入口：简历精修、岗位版本、面试练习。

## 用户流程

1. AI 引用简历原句提出 2—5 个追问。用户逐项填写实际职责、技术取舍或验证结果，并确认用于精修。
2. 改写以不重叠的原文替换建议交付，每条展示原文、新文和事实引用。用户逐条采纳或保留原文；只有采纳内容进入正文。后台拒绝失实引文、把 JD 当个人依据、重叠替换及源材料中没有的阿拉伯数字表达。语义仍需用户核实，不能将这些检查视为完整的真实性保证。
3. 从已保存版本复制新岗位版本，修改名称、JD、正文及确认事实。岗位优化调用同一套改写审核流程。更改正文、JD 或事实会使旧追问与建议失效。版本独立保存，原始诊断材料仍保留在报告中。
4. 导出当前已保存的纯文字，或打开私有的打印页面，使用浏览器“另存为 PDF”。打印页隐藏操作栏，仅排版简历正文；不包含 JD、恢复码、追问或待采纳建议。
5. 选定版本及练习方向，开始 3、5 或 8 题文字面试。系统冻结简历和 JD 快照；每次回答保存后才进入下一轮生成。模型接收此前问题、回答和反馈，并针对最新回答追问。
6. 最后一题产生逐题反馈及综合复盘，包括已有长处、缺口、练习计划。至少回答一题后可以提前结束，仅复盘已答部分。复盘可导出，也可将薄弱点带入新一轮练习。

草稿仅保留在当前页面内存，切换页内步骤时仍可找回；离开或刷新有未保存输入的页面时提醒保存。所选版本及练习的编号保存在当前标签页的 sessionStorage，不在浏览器持久存储简历原文或回答。服务器已保存的版本、回答和任务可以刷新后继续。

## 数据与任务

- SQLite 升级到 schema version 2，通过新增 `preparations` 和 `preparation_tasks` 表保留旧报告、会话及恢复码。
- `preparations` 保存工作台的加密 JSON 和单调递增的 revision。每次更新要求客户端提供当前 revision；事务内重新检查访问权、到期时间、revision 和运行中的任务。
- 生成所需的用户修改与任务入队在同一事务提交。重复回答或旧页面提交返回 409，不会再追加一条回答。
- 任务输入独立加密，重试使用原有快照。成功后清除任务输入副本；准备资料和原报告通过外键级联删除。生成中删除、到期或旧租约返回都不能写回资料。
- AI 任务通过现有 worker 池处理，不增加 worker 数量。诊断和准备交替取任务，合计队列受 `QUEUE_LIMIT` 约束。一份工作台最多一个待处理生成。
- 每个任务最多自动尝试 3 次；仅暂时性网络、超时或上游限流等错误自动重试。最终失败显示错误和手动重试入口，原有正文与回答保留。
- 每份报告最多 8 个版本、6 场面试，每场最多 8 题；每条回答最多 3,000 字符。补充事实累计最多 12,000 字符。
- 所有资料继承原报告到期时间，默认 7 天。本节描述求职准备首版；后续加入账号与人工核款，次数规则见 [billing.md](billing.md)。材料仍不长期保存。

## 接口

| 接口 | 作用 |
|---|---|
| `GET /api/diagnoses/{id}/preparation` | 返回授权工作台、最新任务和到期时间 |
| `POST /api/diagnoses/{id}/preparation` | 通过 action 执行版本、精修与面试操作；校验 CSRF、revision 和生成同意 |
| `GET /api/diagnoses/{id}/versions/{version}/export` | 下载当前保存的简历文字 |
| 同上，`?format=html` | 私有简历打印页面 |

主要 action：`questions`、`rewrite`、`tailor`、`accept_edit`、`reject_edit`、`new_version`、`save_version`、`delete_version`、`start_interview`、`answer`、`finish_interview`、`delete_interview`、`retry`。

## 验证边界

开发联调使用 `scripts/mock-claude.mjs --test-only` 及固定虚构材料。该替身仅验证协议、状态推进和浏览器流程；真实模型的改写质量、追问质量、成本和用户付费意愿均未由这些测试证明。真实样本验收见 `evaluation.md`。
