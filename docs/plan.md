## 当前扩展范围（v2.0）

在首版诊断之后，新增同一份私有资料下的求职准备工作台：

1. **追问式简历精修**：按原文提出问题，保存用户确认的事实，生成有依据的逐段修改；逐条采纳后更新正文。
2. **岗位简历版本与 PDF 导出**：从成稿复制独立岗位版本，编辑正文、目标 JD 和补充事实，保存并在浏览器导出简历 PDF。
3. **文字模拟面试与复盘**：基于选定版本的冻结快照进行 3、5 或 8 题连续追问，保存回答、逐题反馈与复盘，支持提前结束和针对薄弱点再练。

工程上复用 Go、SQLite、匿名访问和恢复码。新增资料加密保存，继承原报告到期时间；所有 AI 任务共用有限 worker 和队列。完整流程、数据约束及接口见[求职准备设计](preparation.md)。

以下保留首版设计作为基础；与首版范围描述有差异时，以本节及求职准备设计中的当前行为为准。计费附录维持原文。

## 1. 首版解决的问题

面向有实际项目经历的后端开发求职者，将一份简历与一个目标岗位 JD 逐项对照，帮助用户看清哪些要求已有证据、哪些经历需要补充、哪些要求尚未在简历中体现。

首版只覆盖后端开发（Go / Java / Python 等共同的工程要求）；不承诺覆盖全部职业，也不预测录用概率。Go + SQLite + 外部模型适合初期部署，可靠性仍需要通过输入限制、访问控制和故障测试验证。

核心交付是一份有来源的对照表和最多三条优先修改建议。暂不实现整份简历自动重写、图片 OCR、公开分享、岗位爬取、支付和会员系统；原有商业设想在附录保留。

## 2. 用户流程与首版范围

1. 粘贴简历文字，或选择文字型 PDF。PDF 在浏览器内提取，用户可检查和修改提取结果，原文件不上传。
2. 粘贴目标岗位 JD，确认用途、服务商和保存期限，再提交分析。
3. 服务生成私有任务，展示真实的排队 / 分析 / 完成 / 失败状态，提供一次性显示的报告恢复码。
4. 阅读逐项对照及引用，区分“已有依据”“待补充”“未体现”。这些分类说明文字中的证据情况，不代表本人实际能力。
5. 阅读优先修改建议，针对缺失信息回答具体问题，确认事实后自行修改简历。
6. 导出 Markdown 或通过浏览器保存 PDF；通过“我的报告”或恢复码再次访问，随时删除。

### 输入边界

- 首版简历为 100—20,000 字符，JD 为 80—12,000 字符。
- PDF 最大 5 MiB、最多 6 页；只处理可提取文字的 PDF。扫描件、图片、加密或损坏文件给出明确提示，允许改为粘贴文本。
- 浏览器按需加载本地 PDF.js，不使用第三方 CDN。提取过程仅在当前设备执行。
- 提取后归一化 PDF 中的兼容汉字，保留供用户检查的文本；引用校验针对用户最终确认并提交的文字。
- 暂不自动保存浏览器草稿，避免在公共设备长期留下简历。

### 诊断可信度

报告包含：岗位要求、JD 原文引用、要求类型、简历原文引用、证据状态、解释，以及最多三条修改建议。

- 每条 JD 引文必须在提交的 JD 中找到；每条简历引文必须在提交的简历中找到，允许空白字符归一化。
- “已有依据”和“待补充”必须附简历引用；“未体现”不允许伪造引用。
- 不生成用户未提供的公司、项目、学历、职位、工作年限或业绩数字。
- 首版输出修改动作和待回答的问题，不输出冒充既有事实的完整改写成稿。
- 缺少数据时明确请求补充；引用校验失败的输出不会作为正常报告交付。
- 系统根据要求列表计算分类计数，不采用模型自行给出的 0—100 分或录用概率。
- 保存模型标识、规则版本及生成时间，支持回溯。同一文本的模型解读可能变化，不承诺绝对可复现。
- 引文校验不能证明语义判断完全正确；界面提示用户核实模型解读。

### 示例模式

未配置真实模型时，网站可以展示一份固定、明确标注的虚构示例，说明报告结构。不会把示例冒充用户材料的 AI 分析。真实提交在服务未就绪时明确不可用，不保存用户材料。

## 3. 技术实现

### 架构

```text
浏览器：原生 HTML / CSS / JavaScript + 按需加载的 PDF.js
   │ 同源 HTTPS，匿名会话 + CSRF 防护
   ▼
Caddy → Go net/http 单进程（内嵌网页资源）
          ├── SQLite：加密材料 / 报告、访问授权、任务状态
          ├── 固定数量 worker：从 SQLite 原子领取任务
          ├── Anthropic Messages API：可配置模型、端点
          └── 到期清理、取消任务、健康检查
```

### 选型

| 部分 | 选择 | 说明 |
|---|---|---|
| 服务 | Go，使用受支持版本构建 | 单二进制，目标服务器无 Node 运行时 |
| HTTP | `net/http` | 同源网页和 JSON API，静态资源 embed |
| 数据库 | `database/sql` + `modernc.org/sqlite` | 纯 Go；WAL、单写连接、busy timeout、参数化 SQL |
| 迁移 | 内嵌 SQL + 版本表 | 首版不引入额外迁移 CLI 或代码生成流程 |
| 前端 | 原生模块和 CSS | 无页面构建步骤，无 CDN；PDF.js 资源在开发机准备 |
| 模型 | Anthropic Messages HTTP API | 不把未验证的模型名或 SDK 签名写死；通过环境变量配置 |
| 部署 | Caddy + systemd | 在开发机构建，再上传二进制；1GB 机器不承担构建任务 |

### 任务可靠性

- SQLite 是任务的事实来源，内存信号仅用于唤醒 worker。
- 默认 2 个 worker，可配置为 1—4 个；队列默认最多 20 个未完成任务。
- 任务使用原子领取、租约、尝试次数及下一次执行时间；租约过期后恢复。
- 对限流、临时网络或上游服务错误有限重试，最多 3 次；无效材料、拒答或不合格报告给出可操作提示。
- 同一会话提交相同材料时复用有效任务，防止重复点击产生重复任务。
- 任务写回必须验证任务仍存在、租约仍归当前 worker 且未过期；删除和到期不会被迟到结果撤销。
- 用户删除任务时取消本地正在执行的请求；远端已经接收的数据按服务商政策处理。
- 明确限制 HTTP 请求体、文本长度、模型响应大小、请求时间和排队数量。

### 数据与访问

- 匿名会话使用高熵随机 Cookie，HttpOnly、SameSite，在 HTTPS 下启用 Secure；数据库仅保存会话令牌摘要。
- 报告使用随机 ID，但随机 ID 不替代授权：列表、查看、导出、删除都验证所属会话或恢复码授予的访问权。
- 恢复码与报告编号独立，创建时只显示一次，服务端仅存摘要；恢复操作限流，码不放进 URL。
- 原始 PDF 不上传、不存储。提交的文字和完整报告使用 AES-GCM 加密保存，密钥与数据库分离。
- 文字和报告统一在提交后 7 天到期；启动时和定时执行清理，查询也检查到期时间。
- 日志不记录材料、模型全文、恢复码、Cookie 或 API Key；返回给浏览器的错误经过清理。
- 本版没有公开分享路由。后续若增加，必须单独授权、脱敏、独立随机令牌、可撤销。

### 接口

```text
GET    /                         工作台
GET    /api/bootstrap            服务可用状态、CSRF、公开配置
GET    /api/example              明确标注的固定示例
GET    /api/diagnoses             当前会话可访问的未过期报告
POST   /api/diagnoses             提交材料，获得任务 ID 和恢复码
GET    /api/diagnoses/{id}        授权后的状态与报告
GET    /api/diagnoses/{id}/export Markdown 导出
DELETE /api/diagnoses/{id}        删除材料、报告和访问权
POST   /api/recover               通过恢复码授予当前会话访问权
GET    /healthz                   进程与数据库检查，不暴露配置和密钥
```

## 4. 界面方向

使用“经历与要求逐项对齐”的文档工作台，而不是制造焦虑的分数仪表盘。

- 色彩：冷白、深墨绿、柔和浅绿；琥珀色仅用于待补充项。
- 字体：中文衬线标题少量使用，正文采用本地系统无衬线字体，编号使用等宽字体；无外部字体请求。
- 首页：简短说明、真实的对照片段示例、简历 / JD 两个输入区。
- 报告：分类计数、可筛选的逐项证据、三条优先建议、导出和删除。
- 支持手机、键盘操作、可见焦点、减少动画偏好。错误信息说明下一步能做什么。

## 5. 验证与验收

### 工程验收

- 自动测试：报告引文校验、输出结构限制、会话隔离、恢复码、到期删除、运行中删除、重复提交、任务恢复、重试和请求限流。
- 模型适配器使用本地模拟上游验证请求结构和失败分支；真实模型质量评估需使用可用的 API 配置，不能将模拟测试当作真实联调。
- 浏览器验收：完整示例、文本提交、PDF 提取及检查、任务轮询、私有报告、恢复、Markdown / PDF 导出、移动端排版。
- 构建适用于目标 Linux 架构的二进制，附 systemd、Caddy、环境变量模板和部署说明。

### 产品验收

准备 10—20 份取得使用授权的后端岗位简历及对应 JD，使用同一评估表盲评：

1. JD 要求提取是否忠实，是否混淆必要项与加分项。
2. 引文是否正确，状态判断是否能由原文支持。
3. 是否新增任何未经确认的个人经历或数字；发现即记为严重错误。
4. 建议是否指出具体段落和明确的补充问题。
5. 用户实际采用哪些建议，哪些建议被拒绝及原因。
6. 与直接向通用 AI 提问的结果相比，是否更稳定、更容易理解和修改。

工程测试通过表示软件流程可运行，不等于模型诊断质量已经通过真人评估。

实施结果：源码位于本仓库根目录，部署步骤见 [DEPLOY.md](../DEPLOY.md)，工程记录见 [verification.md](verification.md)。正常启动缺少模型配置时仅展示固定示例，不接收真实材料。

## 6. 增长与后续范围

首批用户集中在一个后端求职群体。以获得授权的案例对照、真实工具演示和具体写法解释为主要内容，不编造面试结果、HR 内幕或必备关键词。

发布节奏按时间安排试验，不把“每天两篇”视为成功门槛。记录有效访问、提交完成率、报告阅读情况及修改建议采用情况。样本很少时不把单一转化阈值当作产品成败结论。

优先验证报告质量和用户是否真正采用建议，再决定扩展职业、增加改写、支付或公开分享。商业与计费部分仅保留历史设想，不作为本次开发验收项。

## 7. 上线与数据说明

目标为日本服务器。部署地域、运营主体、实际模型接收方和服务政策都需在正式公开前核实并准确告知用户；不把海外托管或“7 天删除”视为已完成全部合规义务。

真实诊断需配置模型端点、模型名和 API Key。密钥仅在服务端，生产环境要求明确配置加密密钥、公开 HTTPS 地址和隐私说明。默认不开启包含用户材料的长期备份；若运营方增加备份，必须另设加密、访问权限与不超过承诺范围的保留周期，恢复前重新清理过期数据。

初期使用单实例，不保证固定内存数值或任意用户规模。通过实际测量检查内存、排队时间、失败率和磁盘占用，再决定扩容。

### 3.6 成本模型

按 `claude-opus-5` 计价($5/百万输入,$25/百万输出),汇率按 ¥7.2/$:

**单次完整诊断:**

| 项 | Token | 成本 |
|---|---|---|
| 系统提示词(缓存读取) | 3,000 | $0.0015 |
| 简历 + JD(非缓存输入) | 2,000 | $0.0100 |
| 报告输出 | 3,000 | $0.0750 |
| **合计** | | **$0.087 ≈ ¥0.62** |

**单次免费版(评分 + 3 条):**

| 项 | Token | 成本 |
|---|---|---|
| 系统提示词(缓存读取) | 3,000 | $0.0015 |
| 简历 + JD | 2,000 | $0.0100 |
| 输出 | 600 | $0.0150 |
| **合计** | | **$0.027 ≈ ¥0.19** |

**单位经济模型(假设免费:付费 = 10:1):**

```
10 个免费用户成本        ¥1.90
 1 个付费用户成本        ¥0.62
──────────────────────────────
总成本  ¥2.52
收入    ¥19.90
毛利    ¥17.38   →  毛利率 87%
```

**¥99 档**:输出约 8000 token,单次成本约 ¥1.58,毛利率 98%。

**结论**:成本不构成任何约束。唯一的成本风险是**被刷**(见 §7.3),不是正常使用。
